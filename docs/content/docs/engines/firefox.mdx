The Firefox engine drives a Firefox install on the local machine over WebDriver BiDi. Snapshots come from Firefox's DevTools accessibility tree, so refs work the same way they do with Chrome.

## Installation

The Firefox engine requires Firefox 150 or newer. agent-browser does not download Firefox as part of `agent-browser install`; install it with your package manager or from Mozilla.

agent-browser finds Firefox on your `PATH` and in standard install locations. To use a specific binary, pass `--executable-path` or set `AGENT_BROWSER_EXECUTABLE_PATH`.

On macOS and Linux, install Firefox 150 or newer. The Snap package is not supported because it cannot use temporary profiles; use the Mozilla tarball and pass `--executable-path`.

## Usage

Set `--engine` on the command that launches the browser. Later commands in the same session use Firefox without the flag:

```bash
agent-browser --engine firefox open example.com
agent-browser snapshot
agent-browser screenshot
```

Or set it as the default via environment variable:

```bash
export AGENT_BROWSER_ENGINE=firefox
agent-browser open example.com
```

Set `engine` in `~/.agent-browser/config.json` or in a trusted file loaded explicitly with `--config`. The auto-discovered `./agent-browser.json` does not support this setting:

```json
{
  "engine": "firefox"
}
```

## Custom Binary Path

If Firefox is not in a standard location, use `--executable-path`:

```bash
agent-browser --engine firefox --executable-path /path/to/firefox open example.com
```

## Profiles

Each launch uses a fresh temporary profile, so cookies and storage start clean unless you restore them with state or a session name. `--profile` is not supported with Firefox.

## Attach to a running Firefox

`agent-browser connect <port|url>` and `--cdp <port|url>` attach to a Firefox started outside agent-browser over WebDriver BiDi. Start Firefox 150 or newer with remote debugging and its DevTools server, and add these prefs to the profile's `user.js`:

```js
user_pref("devtools.debugger.remote-enabled", true);
user_pref("devtools.chrome.enabled", true);
user_pref("devtools.debugger.prompt-connection", false);
```

```bash
firefox --remote-debugging-port 9222 --start-debugger-server 6000 -profile <dir>

agent-browser connect 9222
agent-browser snapshot
agent-browser close
```

Detection is automatic. A `ws://` or `wss://` URL whose path is `/session` is treated as Firefox BiDi. Other targets try CDP first and probe for Firefox only when CDP discovery fails. Pass `--engine firefox` to skip the CDP attempt. Firefox uses the DevTools server on port 6000 unless the URL sets `?devtools=<port>`, for example `agent-browser connect "ws://127.0.0.1:9222/session?devtools=6080"` when Firefox was started with `--start-debugger-server 6080`.

The session starts on the tab selected in Firefox, or on the first tab when none reports itself visible. The attached browser is externally owned: `close` ends the BiDi session and leaves Firefox running. Only one client can hold a Firefox BiDi session at a time, and a client that exits without ending its session keeps it until Firefox restarts. `--auto-connect` does not support Firefox.

Options that need a launch are rejected when attaching: `--profile`, `--args`, `--extension`, `--allow-file-access`, `--webgpu`, and `--ca-cert`. `--headed`, `--executable-path`, and `--no-xvfb` have no effect on an already-running browser. `--allowed-domains` is rejected when attaching, as it is for any pre-existing CDP session. `--pin-tab` and its `tab_gone` guarantee apply only to Chrome over CDP; Firefox attach rejects `--pin-tab`. See [CDP Mode](/cdp-mode) for the full attach workflow.

## Supported features

Navigation, tabs, `eval`, snapshots and refs (including iframes and open shadow roots), all element commands, `find`, frames, dialogs, screenshots (including `--annotate`), PDF, cookies, storage, state save and load with `--session-name` restore, `network route` and `network unroute`, requests, HAR and response bodies, extra headers, offline mode, HTTP auth, `--allowed-domains`, downloads, uploads, emulation (`set viewport`, `set geo`, `set media`, and `--user-agent`), `--proxy`, `--ignore-https-errors`, and the dashboard live view.

On Firefox, HTML5 drag-and-drop uses synthetic DOM events, so handlers that require trusted drag events are unsupported; other pointer dragging uses native pointer input.

Media emulation on Firefox supports only `prefers-color-scheme` and print media. Other media features return an error that lists the supported ones.

`find text` and `find label` search the main document only, like Chrome. The dashboard live view polls screenshots of the active tab and forwards mouse and keyboard input, so it works without screencast.

## Security

When it launches Firefox, the daemon enables Firefox's DevTools server only for the profile it owns. On macOS and Linux the server listens on a private unix socket inside a directory with `0700` permissions. On Windows it listens on a random loopback port.

## When to Use Firefox

Use the Firefox engine when you need to test against Firefox rendering, JavaScript, or accessibility behavior with the same CLI and refs you use for Chrome. Use Chrome when you need Chrome-only commands, Chrome extensions, persistent profiles, or the exact Chrome fingerprint.
