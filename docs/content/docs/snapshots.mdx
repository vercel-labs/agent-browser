The `snapshot` command returns a compact accessibility tree with refs for element interaction.

## Options

Filter output to reduce size:

Compact snapshots (`-c`) fit the tree in a token budget. See [Compact snapshots](#compact-snapshots). Interactive snapshots (`-i`) filter out noninteractive content. MCP snapshots default to interactive; set `interactive: false` to retain visible text and status text.

```bash
agent-browser snapshot                    # Full accessibility tree
agent-browser snapshot -i                 # Interactive elements only (recommended)
agent-browser snapshot -c                 # Compact (fit in about 2000 tokens)
agent-browser snapshot -c --max-tokens 800  # Compact with a smaller budget
agent-browser snapshot -d 3               # Limit depth to 3 levels
agent-browser snapshot -s "#main"         # Scope to CSS selector
agent-browser snapshot -i -c -d 5         # Combine options
```

## Compact snapshots

`snapshot -c` keeps a large page readable within a fixed budget. The default snapshot output does not change.

1. Structural lines with no content below them are removed.
2. Runs of more than 12 adjacent siblings with the same role, such as table rows, list items, select options, and links, keep their first 5 and last 2 items. Items that contain a focused, selected, or checked element are kept too, as are items with interactive content when no more than a quarter of the run has any. Header rows are always kept and are not counted. A marker states how many items were hidden and the total, for example `- … 493 more rows (500 total)`.
3. Text longer than 100 characters is shortened with an ellipsis. Names of interactive elements are never shortened. Text that only repeats a nearby name, such as a label matching its input, is dropped.
4. If the tree is still over budget, lines are kept in priority order with their ancestors, so the output remains a tree. Interactive elements rank first, then headings and landmarks, then labels and text next to controls, then other text. Links inside running text rank just below headings, except in the viewport or in the first paragraph or list under a heading, where they rank with other controls. A link that only repeats its heading, such as a section permalink, ranks with headings. A line kept from a table row brings the row's identifying cell (its row header, or else its first named cell), and a link kept from the paragraph under a heading brings that heading unless a parent such as a named region already shows its name. The focused element is always kept. Content in the viewport and in open dialogs ranks higher, and hidden, offscreen, and collapsed content ranks lower. Each parent with omitted children gets one marker such as `- … 12 more links`.

When anything is omitted, the last line reports how much was shown, for example `(compact: showing 107 of 591 lines; ...)`. To see more, raise `--max-tokens`, scope the snapshot with `-s`, or run it without `-c`.

```bash
agent-browser snapshot -c
# - main
#   - heading "Customers" [level=1, ref=e1]
#   - search
#     - LabelText
#       - searchbox "Filter customers" [ref=e6]
#     - button "Apply filter" [ref=e3]
#   - table "All customers (500)"
#     - rowgroup
#       - row
#         - columnheader "Select all" [ref=e3007]
#           - checkbox "Select all" [checked=false, ref=e4513]
#         ...
#     - row
#       - cell "Select customer 1" [ref=e7]
#         - checkbox "Select customer 1" [checked=false, ref=e3013]
#       ...
#     - … 493 more rows (500 total)
#     ...
#   - navigation "Pagination" [ref=e2]
#     - link "Previous" [ref=e4]
#     - StaticText " Page 2 of 40 "
#     - link "Next" [ref=e5]
# (compact: showing 92 of 5022 lines; use --max-tokens <n>, -s <selector>, or no -c for more)
```

Compaction only hides lines. A compact snapshot assigns the same refs as a full snapshot of the same page, and refs of hidden lines still work with `click`, `fill`, and other commands. `-i` combines with `-c`: the interactive tree is collapsed and budgeted the same way. `-i -c` also prints table rows and the `table`/`rowgroup` lines above them (they have no ref), so a table collapses by whole rows, rows from separate tables never share one collapsed run, and each kept button or link is shown with its row's identifying cell. Plain `-i` output does not change.

The budget is estimated from line length, calibrated against the o200k tokenizer, and errs high, so real token counts usually land at or under the budget. `diff snapshot --compact` only removes empty structure and does not apply a budget, so diffs stay complete.

## Output format

The default text output is compact and AI-friendly:

```bash
agent-browser snapshot -i
# Output:
# @e1 [heading] "Example Domain" [level=1]
# @e2 [button] "Submit"
# @e3 [input type="email"] placeholder="Email"
# @e4 [link] "Learn more"
```

## Using refs

Refs from the snapshot map directly to commands:

```bash
agent-browser click @e2      # Click the Submit button
agent-browser fill @e3 "a@b.com"  # Fill the email input
agent-browser get text @e1        # Get heading text
```

## Ref lifecycle

Surviving DOM elements retain their refs across snapshots and same-document updates. Replacing an element or navigating its page or iframe invalidates its refs without recycling IDs. Virtual accessibility nodes have snapshot-local refs. Re-snapshot after interactions to observe changes, and always after navigation:

```bash
agent-browser click @e4      # Navigates to new page
agent-browser snapshot -i    # Get fresh refs
agent-browser click @e8      # Use a ref from the new snapshot
```

A ref keeps pointing at its DOM node while that node exists. If the node was replaced, agent-browser falls back to the one element with the same role and name, but only when the ref was unique in its snapshot. When duplicates make the match ambiguous, the action fails without acting. Run `snapshot` again and use a fresh ref.

## Annotated screenshots

For visual context alongside text snapshots, use `screenshot --annotate` to overlay numbered labels on interactive elements. Each label `[N]` maps to ref `@eN`:

In native mode, annotated screenshots currently work on the CDP-backed browser path (Chromium/Lightpanda). The Safari/WebDriver backend does not yet support `--annotate`.

```bash
agent-browser screenshot --annotate ./page.png
# -> Screenshot saved to ./page.png
#    [1] @e1 button "Submit"
#    [2] @e2 link "Home"
#    [3] @e3 textbox "Email"
agent-browser click @e2
```

Headless Chromium screenshots hide native scrollbars for consistent image output. Pass `--hide-scrollbars false` when launching to keep native scrollbars visible.

Annotated screenshots also cache refs, so you can interact with elements immediately. This is useful when the text snapshot is insufficient for unlabeled icons, canvas content, or visual layout verification.

## Iframes

Presentational iframes use the same `Iframe` role for snapshots and stale-ref recovery.

Snapshots automatically detect and inline iframe content. Each `Iframe` node in the main frame is resolved and its child accessibility tree is included directly beneath it. Refs assigned to elements inside iframes carry frame context, so interactions work without switching frames first.

```bash
agent-browser snapshot -i
# @e1 [heading] "Checkout"
# @e2 [Iframe] "payment-frame"
#   @e3 [input] "Card number"
#   @e4 [button] "Pay"

agent-browser fill @e3 "4111111111111111"
agent-browser click @e4
```

Only one level of iframe nesting is expanded. Cross-origin iframes that block accessibility tree access and empty iframes are silently omitted.

To scope a snapshot to a single iframe, switch into it first:

```bash
agent-browser frame @e2
agent-browser snapshot -i       # Only elements inside that iframe
agent-browser frame main        # Return to main frame
```

## Best practices

1. Use `-i` to reduce output to actionable elements
2. Re-snapshot after page changes to get updated refs
3. Scope with `-s` for specific page sections
4. Use `-d` to limit depth on complex pages
5. Use `screenshot --annotate` when visual context is needed alongside refs

## JSON output

For programmatic parsing in scripts:

```bash
agent-browser snapshot --json
# {"success":true,"data":{"snapshot":"...","refs":{"e1":{"role":"heading","name":"Title"},...}}}
```

Note: JSON uses more tokens than text output. The default text format is preferred for AI agents.
